# campus-net-toolkit

> 校园网（以及酒店、公司、任何受限网络）下的诊断与绕过工具箱。
> **零依赖** —— 只用 Python 标准库。

## 先说一个我犯过的错

我在校园网下连不上外网，随手测了几个公共 DNS：

```
223.5.5.5        超时
119.29.29.29     超时
114.114.114.114  超时
8.8.8.8          超时
```

四个全挂。于是我得出了结论：**「学校把 DNS 封了」**。

然后我花了几个小时研究怎么绕过 DNS —— 把域名的 IP 逐个 TLS 校验后钉进 `hosts`，
写自愈脚本，做看门狗……

**直到我偶然读到系统自己配的 DNS：**

```
$ campusnet dnsfind

  服务器            来源         UDP       TCP       解析结果
  ------------------------------------------------------------------
  192.0.2.53        系统配置     20ms      40ms      110.242.69.21   ← 通
  192.0.2.54        系统配置     20ms      41ms      110.242.69.21   ← 通
  ------------------------------------------------------------------
  223.5.5.5        公共         ✗         ✗
  119.29.29.29     公共         ✗         ✗
  114.114.114.114  公共         ✗         ✗
  8.8.8.8          公共         ✗         ✗
  1.1.1.1          公共         ✗         ✗
  180.76.76.76     公共         ✗         ✗

  可用服务器  2
  建议使用：192.0.2.53（系统配置）
```

**学校没封 DNS。学校有自己的解析器，20 毫秒就返回。**
**我只是从来没问过系统「你现在用的是哪台」。**

这个工具就是从那次的教训里长出来的 —— **它的第一条命令就是「先问系统」。**

## 它解决什么

校园网/受限网络的限制通常是这六类，**每类的解法完全不同**，而症状看起来一模一样（"网断了"）：

| 限制 | 症状 | 怎么判断 | 怎么绕 |
|---|---|---|---|
| **认证门户** | 连上了但什么都没网 | 明文 HTTP 请求被重定向到登录页 | 登录 |
| **DNS 被拦** | 能通 IP、打不开域名 | 公共 DNS 全挂但系统 DNS 通 | **用系统 DNS**，别改 |
| **UDP/53 封锁** | DNS 时好时坏 | 同一台服务器 UDP 超时、TCP 正常 | 走 TCP 或换服务器 |
| **客户端隔离** | 同网段设备互相看不见 | 扫本网段一台都没有，但网关通 | 走热点或中继 |
| **端口封锁** | 只有 80/443 能用 | 直连 IP 逐个端口试 | 换端口或走隧道 |
| **MTU 问题** | 网页能开、传文件卡死 | 小包通、大包超时 | 调 MTU 到 1400 |

**这个工具的价值不在于"帮你连上网"，而在于告诉你**：

> **到底是哪一类限制，以及为什么学校要这么干。**

因为「网断了」这三个字，背后可能是六个完全不同的原因，用错解法只会浪费一晚上。

## 安装

**不需要安装。**

```bash
git clone https://github.com/lichj06/campus-net-toolkit
cd campus-net-toolkit
python3 -m campusnet diagnose
```

没有依赖，没有虚拟环境，没有 `pip install`。只要有 Python 3.8+。

（如果你想装成命令：`pip install -e .`，然后可以直接用 `campusnet`。）

## 用法

### `diagnose` —— 网络体检

一次跑完，给出结论。

```bash
python3 -m campusnet diagnose
```

```
================================================================
1. 认证门户（Captive Portal）
================================================================
  原理：没认证时，网关会把明文 HTTP 请求劫持到登录页。
        所以看「有没有被重定向」即可判断。

  [OK]   明文 HTTP  223.5.5.5 (阿里 DNS)     83 ms   HTTP 404（正常，无劫持）

  [OK]   没有门户劫持 —— 要么已认证，要么这个网络不需要认证

================================================================
2. DNS
================================================================
  系统配置的 DNS    192.0.2.53, 192.0.2.54
         提示：cat /etc/resolv.conf

  [OK]   测试 192.0.2.53     19 ms   可用 -> 110.242.69.21
  [OK]   测试 192.0.2.54     19 ms   可用 -> 110.242.69.21

         对照：公共 DNS 在这个网络下能不能用
  [FAIL] 公共 223.5.5.5    7008 ms  TimeoutError
  [FAIL] 公共 119.29.29.29 7008 ms  TimeoutError
  [FAIL] 公共 8.8.8.8      7007 ms  TimeoutError

================================================================
4. 端口与外网可达性（全部用 IP，不依赖 DNS）
================================================================
  意义：把「DNS 坏了」和「网络真的不通」分开。

  [FAIL] 阿里 DNS (UDP/53 对照)   223.5.5.5:53       3004 ms  TimeoutError
  [OK]   阿里 DNS (443)          223.5.5.5:443        70 ms   连上了
  [FAIL] 腾讯 DNS                119.29.29.29:53     3002 ms  TimeoutError
  [FAIL] Google DNS              8.8.8.8:53          3003 ms  TimeoutError

  可达  1 / 6
  [WARN] 部分可达 —— 存在端口封锁

================================================================
结论
================================================================
  1. 用系统配置的 DNS     公共 DNS 在这个网络下不可用，别去改它
  2. 部分端口被封         换端口或走隧道
```

**注意第 4 节的设计**：所有目标都用 **IP**，不用域名。
因为如果 DNS 本身是坏的，任何"先解析再连接"的测试都会失败 ——
但那是 DNS 的锅，不是目标服务的锅。**两者必须分开测，否则你会得到一堆积压的假阴性。**

### `dnsfind` —— 找出能用的 DNS

```bash
python3 -m campusnet dnsfind
```

**UDP 和 TCP 分别测。** 实测遇到过：同一台服务器 UDP 查询 3 秒超时、TCP 查询 3 毫秒返回。
只测 UDP 会得出「这台不能用」的错误结论。

```bash
python3 -m campusnet dnsfind --apply    # 顺便写进系统配置
```

### `pin` —— 把域名钉进 hosts

系统 DNS 也不可用时的最后一招：**彻底不查 DNS。**

```bash
python3 -m campusnet pin api.deepseek.com
```

```
  解析来源         192.0.2.53
  候选 IP          123.125.246.121, 60.28.220.199

  逐个做 TLS 证书校验（确认这些 IP 真的是 api.deepseek.com）
    123.125.246.121    ✅ 证书通过
    60.28.220.199      ✅ 证书通过

  [OK] 已写入 /etc/hosts（2 条）
```

> **每个 IP 都会做一次 TLS 证书校验**（连到 IP:443，用目标域名做 SNI，验证证书链）。
> 不通过的直接丢弃。
>
> 不能随便从别处抄一个 IP 就信 —— 那等于把流量交给一个陌生服务器。

```bash
python3 -m campusnet unpin api.deepseek.com    # 撤掉
```

### `lanfind` —— 在局域网里找设备

```bash
python3 -m campusnet lanfind
```

**它会诚实告诉你结论的可靠性：**

```
  网关可达    未知（网关是猜的，不作证据）

  没有扫到任何设备
         拿不到可信的网关地址 → 无法区分「真隔离」和「网络本身不通」
```

手机上常常读不到路由表（没有 `ip` 命令），只能按 `X.Y.Z.1` 猜。
**猜错的时候不能拿它当证据** —— 否则会得出「网络层不通」这种错误结论。

### `watch` —— 网络看门狗

网络出问题时，你**往往没法当场诊断** —— 因为诊断工具本身需要网络。
等你回到能上网的地方，现场已经没了。

```bash
python3 -m campusnet watch --target 223.5.5.5:443 --hours 8
```

它常驻，盯三个信号：**IP 变了**、**目标从通变不通**、**从不通变通**。
任何一个触发，立刻把当时的完整现场（DNS 状态、端口可达性、局域网扫描）写进日志。

## 平台支持

| 平台 | 读系统 DNS | 说明 |
|---|---|---|
| **Linux** | `/etc/resolv.conf` + `resolvectl status` | ✅ |
| **macOS** | `scutil --dns` | ✅ |
| **Windows** | `Get-DnsClientServerAddress` | ✅ 需要 PowerShell（系统自带） |
| **Android (Termux/proot)** | `/etc/resolv.conf` | ⚠️ 读不到路由表，网关靠猜 |

**读系统 DNS 的 Windows 实现是本项目最有价值的一段代码** —— 就是靠它发现了校园网自己的解析器。

## 写在最后：为什么学校要这么干

这些限制大多不是"刁难"，而是有理由的：

- **客户端隔离** —— 防止 ARP 欺骗和蠕虫横向传播。一台中毒的笔记本能在五分钟内感染整栋楼。
  学校网络的信任假设是「每个设备都可能是威胁」，家用路由器则是「我们是一家人」。
  **这是设计目标，不是 bug。**
- **出口认证** —— 记录谁在什么时候用了网络。《网络安全法》对公共场所网络有实名要求。
- **DNS 只给校内解析器** —— 便于过滤和审计，也降低了被 DNS 污染影响的面。
- **端口封锁** —— 抑制 P2P、挖矿、私搭服务。

**理解这些之后，你会发现"和它对抗"通常不是好策略，"绕开它"才是** ——
比如设备互联，直接开手机热点让手机当网关，比研究怎么穿透隔离简单一百倍。

## 局限

- **它不能让你上网。** 认证没过、出口封了，这个工具帮不了你。
- **`pin` 是临时手段。** IP 会变，钉死的记录迟早失效。系统 DNS 可用时优先用它。
- **`lanfind` 的结论强度取决于能否读到路由表**（见上）。
- **`watch` 只记录，不告警。** 需要推送的话得自己接。
